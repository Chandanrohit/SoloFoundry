# SoloFoundry roadmap

The roadmap prioritizes a useful, trustworthy knowledge base over premature software or AI features. A phase is complete when its deliverables are usable and reviewed—not merely when folders exist.

## Phase 0 — Repository and editorial baseline
- [x] Mission, principles, lifecycle map and information architecture
- [x] Guide template, contribution process and source-evaluation policy
- [x] Resolve project license split: educational text and diagrams CC BY 4.0; code MIT
- [x] Add reader paths and explicitly distinguish topic maps from complete guides
- [ ] Publish vector/source logo variants and confirm asset provenance
- [ ] Decide whether to add a generated website or keep GitHub as the primary reader experience

## Phase 1 — Opportunity intelligence
- [x] Problem signals and research methods
- [x] Customer interview practice, ethical handling, synthesis and limits
- [x] Jobs, workflow mapping, roles and pain analysis
- [x] Segment definition, market sizing method and competitor/substitute analysis
- [x] Assumptions, evidence quality, validation experiments and decision framework
- [x] Hypothetical worked example with explicit limits
- [ ] Independent review of all discovery guides and source links
- [ ] Add a traceable, real case study only with consent and verifiable evidence

## Phase 2 — Product and design
- [x] Product brief, PRD framing and scope control
- [x] User journeys, information architecture and prototyping
- [x] UX research and usability testing
- [x] Accessibility, design systems and content design
- [ ] Independent editorial review and a user-tested product case study

## Phase 3 — Core product engineering
- [x] Frontend/backend boundaries, API contracts, and database fundamentals
- [x] Architecture styles and decision criteria
- [x] Testing, performance, reliability, and maintainability foundations
- [x] Authentication/authorization boundaries, billing concepts, and integrations
- [ ] Independent editorial review and framework-specific tested examples

## Phase 4 — AI engineering (guide set drafted; review and tested examples remain)
- [x] LLM application patterns, non-AI baseline, model/hosting selection, and product boundaries
- [x] Retrieval/RAG pipeline, data lifecycle, authorization, citations, and evaluation method
- [x] Bounded tool-using workflows, permissions, human confirmation, and abuse testing
- [x] Evaluation datasets, rollout, monitoring, latency/cost, and recovery guidance
- [x] Hands-on RAG evaluation lab and reusable evaluation-plan template
- [ ] Independent technical/editorial review and a tested reference implementation

## Phase 5 — Secure delivery and operations (guide set drafted; review and tested examples remain)
- [x] Practical threat modeling, secure defaults, privacy boundaries, and standards
- [x] Deployment-shape decisions, release pipeline, migration, rollback, and CI security
- [x] Service indicators, observability, incident handling, backup and restore concepts
- [x] Solo-friendly operating cadence and recovery priorities
- [ ] Independent review, provider-specific tested walkthroughs, and a restore tabletop

## Phase 6 — Business and growth
- [ ] Positioning, messaging, content and SEO/GEO
- [ ] Distribution, launch and growth experiments
- [ ] Pricing, unit economics, cash flow and business models
- [ ] Legal, privacy, contracts and customer support basics

## Phase 7 — Industry playbooks and integrated examples
- [ ] FinTech, healthcare, legal, manufacturing, retail and education
- [ ] Problem-to-product architecture case studies
- [ ] Stack combinations with cost and operational profiles

## Phase 8 — Editorial quality and navigation
- [ ] Add audience-based paths for idea-stage, active-product and discipline-specific readers
- [ ] Add review ownership, source freshness and update triggers for time-sensitive guidance
- [ ] Add automated local-link, Markdown and metadata checks
- [ ] Add contribution pull-request checklist and clear review workflow

## Phase 9 — Optional discovery tooling
Only after the documentation is useful and maintained: searchable catalogue, structured metadata, interactive decision trees, and an AI-assisted navigator that cites sources and exposes uncertainty.
